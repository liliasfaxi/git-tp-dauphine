## Fusionner
{: .d-inline-block }

Séance 7
{: .label .label-blue }

| Commande | En français |
|---|---|
| `git switch main` | Je me place sur la branche qui doit **recevoir** |
| `git merge <branche>` | J'y intègre l'autre branche |
| `git branch -d <branche>` | Je supprime la branche une fois fusionnée |

**On fusionne toujours vers la branche où l'on se trouve.**

| Message de Git | Ce qui s'est passé |
|---|---|
| `Fast-forward` | `main` n'avait pas bougé : le pointeur avance, aucun commit créé |
| `Merge made by the 'ort' strategy` | Les deux branches avaient avancé : Git crée un **commit de fusion** |
| `CONFLICT` | Les deux ont modifié la **même ligne** : Git ne peut pas choisir |

## Résoudre un conflit
{: .d-inline-block }

Séance 7
{: .label .label-blue }

Un conflit n'est pas une erreur. C'est une **question que Git vous pose**.

Dans le fichier, il écrit :

```
<<<<<<< HEAD
la version de la branche où je suis
=======
la version de la branche que j'intègre
>>>>>>> nom-de-la-branche
```

### Les quatre gestes

1. Ouvrir le fichier, choisir ce qui doit rester
2. **Supprimer les trois lignes de marqueurs** `<<<<<<<`, `=======`, `>>>>>>>`
3. `git add <fichier>`
4. `git commit`

| Commande | En français |
|---|---|
| `git status` | Quels fichiers sont encore en conflit ? |
| `git diff` | Que se disputent les deux versions ? |
| `git merge --abort` | J'annule tout, je reviens avant la fusion |

{: .note }
> Vous pouvez garder l'une des versions, l'autre, ou écrire un mélange
> des deux. C'est vous qui décidez — Git ne fait qu'exposer le désaccord.
