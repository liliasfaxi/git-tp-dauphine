### Séance 7 — Fusionner et résoudre les conflits

**Réunir deux branches**

| Commande | Ce qu'elle fait |
|:---|:---|
| `git merge <branche>` | ramène le travail de `<branche>` **dans la branche où vous êtes** |
| `git merge origin/<branche>` | idem, mais depuis une branche du serveur (après `git fetch`) |
| `git merge --abort` | annule une fusion en cours et remet tout comme avant |

**Les deux réponses possibles de `git merge`**

| Ce que Git affiche | Ce qu'il a fait |
|:---|:---|
| `Fast-forward` | il a juste avancé l'étiquette : la branche d'arrivée n'avait rien de nouveau. Aucun commit créé. |
| `Merge made by the 'ort' strategy` | les deux branches avaient avancé : il a créé un commit de fusion à **deux parents** |
| `CONFLICT (content): ...` | les deux branches ont modifié **la même ligne** : à vous de trancher |

**Les quatre gestes du conflit, dans l'ordre**

| # | Geste | Pourquoi |
|:--|:---|:---|
| 1 | `git status` | où suis-je, quel fichier bloque |
| 2 | ouvrir le fichier | enlever les balises, écrire la bonne version |
| 3 | `git add <fichier>` | dire à Git que c'est réglé |
| 4 | `git commit` | terminer la fusion |

Sortie de secours à tout moment avant l'étape 4 : `git merge --abort`.

**Lire les balises de conflit**

```
<<<<<<< HEAD          ← début de VOTRE version
  ma ligne
=======               ← la frontière
  la ligne qui arrive
>>>>>>> autre-branche ← fin de la version qui arrive
```

Résoudre = supprimer les trois balises **et** la version dont on ne veut pas.

**Ranger ses branches**

| Commande | Ce qu'elle fait |
|:---|:---|
| `git branch -d <nom>` | supprime **seulement si** le travail est déjà ailleurs — le garde-fou |
| `git branch -D <nom>` | supprime quoi qu'il arrive — quand on sait ce qu'on perd |
| `git branch -a` | liste toutes les branches, locales **et** celles du serveur |

> `error: the branch '<nom>' is not fully merged` n'est pas une erreur : c'est le garde-fou de `-d` qui fait son travail.
