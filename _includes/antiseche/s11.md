## Relire une contribution
{: .d-inline-block }

Séance 11
{: .label .label-blue }

Dans l'onglet **Files changed** d'une Pull Request :

| Action | Quand |
|---|---|
| **Comment** | Je pose une question, je signale un détail |
| **Approve** | C'est bon pour moi, ça peut être fusionné |
| **Request changes** | Il manque quelque chose d'important |

Une bonne relecture est **précise** (sur une ligne, pas en général),
**explicative** (pourquoi, pas seulement quoi) et **bienveillante**
(on relit du code, pas une personne).

## Les issues
{: .d-inline-block }

Séance 11
{: .label .label-blue }

| Élément | À quoi ça sert |
|---|---|
| **Issue** | Une tâche, un bug, une idée |
| **Label** | Sa nature : `bug`, `documentation`, `amélioration` |
| **Assignee** | Qui s'en occupe |

Écrire `Closes #12` dans un message de commit ferme automatiquement
l'issue 12 quand la PR est fusionnée.
