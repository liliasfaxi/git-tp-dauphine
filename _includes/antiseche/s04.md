## Les dépôts distants
{: .d-inline-block }

Séance 4
{: .label .label-blue }

| Commande | En français |
|---|---|
| `git remote add origin <adresse>` | Je relie mon dépôt local à GitHub |
| `git remote -v` | Quelles adresses distantes ai-je ? |
| `git remote set-url origin <adresse>` | Je corrige l'adresse |
| `git remote remove origin` | Je supprime le lien (rien n'est perdu) |
| `git clone <adresse>` | Je récupère un dépôt entier, historique compris |
| `git push -u origin main` | J'envoie mon travail, **la première fois** |
| `git push` | J'envoie mon travail, les fois suivantes |

`origin` est le surnom du dépôt distant. Ce n'est pas un mot réservé,
c'est la convention.

### Markdown

| J'écris | J'obtiens |
|---|---|
| `# Titre` | un grand titre |
| `## Sous-titre` | un titre de section |
| `**gras**` | du gras |
| `*italique*` | de l'italique |
| `` `code` `` | du code |
| `- élément` | une puce |
| `1. élément` | une liste numérotée |
| `- [ ] à faire` | une case à cocher |
| `- [x] fait` | une case cochée |
| `[texte](adresse)` | un lien |
| `![texte](image.png)` | une image |
| `> citation` | une citation |

Sur GitHub, la barre au-dessus des zones de saisie insère la syntaxe à
votre place, et `/` ouvre un menu de commandes rapides.

### Les fichiers d'un projet

| Fichier | Rôle |
|---|---|
| `README.md` | Ce qu'est le projet |
| `LICENSE` | Ce que les autres ont le droit d'en faire |
| `CONTRIBUTING.md` | Comment contribuer |
| `CODE_OF_CONDUCT.md` | Les règles de la communauté |
| `CODEOWNERS` | Qui doit relire quoi |
| `.gitignore` | Ce que Git doit ignorer |

### Les niveaux d'accès à un dépôt

`Read` → `Triage` → `Write` → `Maintain` → `Admin`

Se règlent dans **Settings → Collaborators**.
