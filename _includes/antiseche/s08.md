## Fork et Pull Request
{: .d-inline-block }

Séance 8
{: .label .label-blue }

Un **fork** est une copie d'un dépôt sur votre propre compte. Vous y
avez tous les droits, et vous pouvez proposer vos modifications au
dépôt d'origine par une **pull request**.

### Le parcours complet

| Étape | Où |
|---|---|
| **Fork** — je copie le dépôt sur mon compte | GitHub, bouton *Fork* |
| **Clone** — je le récupère chez moi | `git clone <mon-fork>` |
| **Branche** — je travaille à l'écart | `git switch -c ma-fonctionnalite` |
| **Commit** — je valide | `git add` puis `git commit` |
| **Push** — j'envoie sur mon fork | `git push -u origin ma-fonctionnalite` |
| **Pull request** — je propose | GitHub, *Compare & pull request* |

### Les deux dépôts distants

| Nom | Ce qu'il désigne |
|---|---|
| `origin` | **Mon fork**, celui où je peux pousser |
| `upstream` | **Le dépôt d'origine**, que je ne peux que lire |

| Commande | En français |
|---|---|
| `git remote add upstream <adresse>` | Je garde un lien vers le dépôt d'origine |
| `git fetch upstream` | Je vois ce qui a changé chez l'original |
| `git remote -v` | Quels distants ai-je ? |

### Les workflows

| Nom | Principe |
|---|---|
| **GitHub Flow** | Une branche par fonctionnalité, une PR, on fusionne dans `main`. Simple, le plus répandu. |
| **Feature Branch** | Même idée, sans obligation de passer par une PR |
| **Git Flow** | Branches `develop`, `release`, `hotfix`. Lourd, réservé aux projets à versions |

**On ne pousse jamais directement sur `main`.** On propose, on relit, on
fusionne.
