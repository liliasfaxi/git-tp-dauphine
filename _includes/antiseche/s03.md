## Se connecter à GitHub
{: .d-inline-block }

Séance 3
{: .label .label-blue }

| Commande | Ce qu'elle fait |
|---|---|
| `ls -al ~/.ssh` | Ai-je déjà une clé ? |
| `ssh-keygen -t ed25519 -C "adresse"` | Je fabrique ma paire de clés |
| `eval "$(ssh-agent -s)"` | Je démarre l'agent |
| `ssh-add ~/.ssh/id_ed25519` | Je charge ma clé dans l'agent |
| `ssh-add -l` | Quelles clés sont chargées ? |
| `cat ~/.ssh/id_ed25519.pub` | J'affiche ma clé **publique** |
| `ssh -T git@github.com` | Je teste ma connexion |

Sur macOS, préférez `ssh-add --apple-use-keychain ~/.ssh/id_ed25519` :
la clé reste chargée après redémarrage.

### Les deux fichiers

| Fichier | Nature | Où il va |
|---|---|---|
| `id_ed25519` | **Privée** | Ne quitte jamais votre machine |
| `id_ed25519.pub` | **Publique** | Se donne à GitHub |

Une clé publique commence par `ssh-ed25519` et tient sur **une seule
ligne**. Si vous voyez `BEGIN OPENSSH PRIVATE KEY`, vous avez pris la
mauvaise.

### La réponse qui veut dire que tout va bien

```
Hi votre-nom! You've successfully authenticated,
but GitHub does not provide shell access.
```

La seconde phrase n'est pas une erreur.

### Pour copier sa clé publique

| Système | Commande |
|---|---|
| macOS | `pbcopy < ~/.ssh/id_ed25519.pub` |
| Windows | `clip < ~/.ssh/id_ed25519.pub` |
| Linux | `cat ~/.ssh/id_ed25519.pub` |

### Le vocabulaire des comptes

| Terme | Ce que c'est |
|---|---|
| Compte **personnel** | Le vôtre. Un seul par personne. |
| **Organisation** | Regroupe des dépôts, des membres et des équipes |
| **Entreprise** | Regroupe plusieurs organisations |
| Dépôt **public** | Lisible par n'importe qui, sans compte |
| Dépôt **privé** | Vous et les personnes que vous invitez |
