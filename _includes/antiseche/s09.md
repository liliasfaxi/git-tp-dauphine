## Relire une contribution
{: .d-inline-block }

Séance 9
{: .label .label-blue }

Dans une pull request, onglet **Files changed** :

| Action | Quand l'utiliser |
|---|---|
| **Comment** | Je pose une question, je signale un détail |
| **Approve** | C'est bon pour moi, ça peut être fusionné |
| **Request changes** | Il manque quelque chose d'important |

Cliquez sur le **+** en marge d'une ligne pour commenter cette ligne
précise. Groupez vos remarques avec **Start a review**, puis envoyez-les
d'un coup avec **Submit review**.

### Les onglets d'une pull request

| Onglet | Contenu |
|---|---|
| **Conversation** | La discussion, les commits, les vérifications |
| **Commits** | Le détail de chaque commit proposé |
| **Files changed** | Les modifications ligne à ligne |

Une **draft pull request** signale un travail en cours : elle ne peut
pas être fusionnée tant qu'on ne la marque pas comme prête.

### Une bonne relecture

- **Précise** — sur une ligne, pas « c'est à revoir »
- **Explicative** — pourquoi, pas seulement quoi
- **Bienveillante** — on relit du code, pas une personne

## Les issues
{: .d-inline-block }

Séance 9
{: .label .label-blue }

| Élément | À quoi ça sert |
|---|---|
| **Issue** | Une tâche, un bug, une idée |
| **Label** | Sa nature : `bug`, `documentation`, `amélioration` |
| **Assignee** | Qui s'en occupe |
| **Milestone** | À quelle échéance elle se rattache |

Écrire **`Closes #12`** dans un message de commit ou dans la description
d'une pull request ferme automatiquement l'issue 12 à la fusion.

Depuis une issue, **Create a branch** crée une branche déjà reliée à
cette issue.

## Organiser le travail
{: .d-inline-block }

Séance 9
{: .label .label-blue }

Onglet **Projects** d'un dépôt.

| Vue | Ce qu'elle montre |
|---|---|
| **Board** | Un tableau Kanban, une colonne par état |
| **Table** | Un tableau, comme un tableur |
| **Roadmap** | Les éléments placés dans le temps |

| Colonne | Ce qu'on y met |
|---|---|
| **Todo** | Tout ce qui reste à faire |
| **In progress** | Ce sur quoi quelqu'un travaille en ce moment |
| **Done** | Ce qui est fusionné dans `main` |

Les **workflows** déplacent les cartes automatiquement : une issue
fermée passe seule en *Done*.

**Une issue = une branche = une pull request.**

Règle d'équipe : pas plus de deux cartes en cours par personne.
