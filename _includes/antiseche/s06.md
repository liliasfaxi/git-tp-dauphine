## Commits et historique
{: .d-inline-block }

Séance 6
{: .label .label-blue }

| Commande | En français |
|---|---|
| `git log` | L'historique détaillé |
| `git log --oneline` | Une ligne par commit |
| `git log --oneline --graph --all` | L'historique dessiné, toutes branches |
| `git log -3` | Les trois derniers commits |
| `git show <identifiant>` | Que contient ce commit ? |

Chaque commit porte un **identifiant** (un SHA) calculé à partir de son
contenu, de son auteur et de sa date. Les sept premiers caractères
suffisent à le désigner.

### Un bon message de commit

- À l'impératif : « Ajoute », « Corrige » — pas « Ajouté » ni « modifs »
- Court et précis : moins de 50 caractères pour la première ligne
- Il dit **pourquoi**, pas seulement quoi
- S'il contient « et », c'est qu'il fallait deux commits

| Mauvais | Bon |
|---|---|
| `update` | `Corrige la couleur du menu au survol` |
| `fix bug et ajout fiche` | deux commits séparés |
| `Ajouté des trucs` | `Ajoute trois fiches sur les transports` |

## Les branches
{: .d-inline-block }

Séance 6
{: .label .label-blue }

| Commande | En français |
|---|---|
| `git branch` | Quelles branches existent ? Où suis-je ? |
| `git switch -c <nom>` | Je crée une branche et je m'y place |
| `git switch <nom>` | Je me place sur une branche existante |
| `git switch -` | Je reviens à la branche précédente |
| `git branch -d <nom>` | Je supprime une branche devenue inutile |
| `git push -u origin <nom>` | J'envoie ma branche sur GitHub |

**Une branche est un pointeur sur un commit, pas une copie du projet.**
Changer de branche ne duplique rien : Git réécrit simplement les
fichiers de votre dossier.

### Avant de changer de branche

Validez votre travail, ou mettez-le de côté :

| Commande | Ce qu'elle fait |
|---|---|
| `git stash` | Je range mes modifications en cours, sans les valider |
| `git stash list` | Qu'ai-je mis de côté ? |
| `git stash pop` | Je remets ce que j'avais rangé |
